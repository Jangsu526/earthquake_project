# DAY 17 — JSON 입력과 3채널 시각화

## 사용 방법

Node.js 20.9 이상에서 `seismic-ai-dashboard` 경로의 `npm run dev`로 실행한다. 기존 FastAPI와 PostgreSQL도 실행되어 있어야 실제 추론 및 저장이 완료된다.

입력 카드에서 다음 중 하나를 선택한다.

1. **STEAD 샘플**: 기존 `152A.N4_20180623135517_EV`를 선택한다. 서버에 저장된 HDF5 `[100:1100, :]` 구간을 사용한다.
2. **JSON 붙여넣기**: 데이터를 붙여넣고 **JSON 검증 및 파형 표시**를 누른다. 입력을 수정하면 다시 검증해야 한다.
3. **JSON 파일**: `.json` 파일을 선택한다. 파일을 브라우저에서 읽고 자동 검증한다. 최대 크기는 1 MiB다. 검증 전에는 서버에 파형을 전송하지 않는다.

검증 후 채널 1·2·3 파형과 샘플 ID를 확인하고 **AI 추론 실행**을 누른다. 추론 성공 시 실제 클래스, 신뢰도, 샘플 ID 및 PostgreSQL 기록 ID를 표시한다. `data/stead-sample.json`은 붙여넣기와 파일 입력을 확인할 수 있는 실제 1000×3 JSON 예제다.

## JSON 형식

두 가지 형식을 지원한다.

- 배열: 정확히 1000개의 `[숫자, 숫자, 숫자]` 행으로 구성된 2차원 배열
- 객체: `{"sample_id":"my_sample_001","waveform": ...}`에서 waveform에 같은 2차원 배열을 넣는다.

sample_id는 생략할 수 있으며, 생략하면 브라우저가 `JSON_<UUID>`를 생성한다. 직접 지정할 때는 영문 또는 숫자로 시작하고 영문·숫자·밑줄·마침표·하이픈으로 구성된 1~120자여야 한다. 같은 ID를 다시 추론해도 기존 API 동작대로 새 기록이 생성된다.

위 설명의 `...`는 생략 기호이며 유효한 JSON이 아니다. 실제 데이터에는 모든 1000개 행이 있어야 한다.

## 검증 및 시각화

`app/inference-contract.ts`의 공통 검증을 브라우저와 Next.js 서버에서 모두 사용한다.

- 정확히 1000개 시점과 각 시점당 3개 채널
- 숫자 타입만 허용: 문자열, boolean, null, 누락값 거부
- NaN·무한대 및 JSON 숫자 오버플로(`1e400`) 거부
- 모델의 float32 범위를 벗어나는 값 거부
- JSON 문법 오류 및 1 MiB 초과 입력 거부

검증 실패 시 행과 채널 위치를 한국어로 표시하고 파형·기존 결과를 지운다. 검증되지 않은 입력에서는 추론 버튼을 비활성화한다. 입력 방식을 바꾸거나 초기화해도 이전 검증과 결과를 지운다. 진행 중에는 입력 변경과 중복 추론을 막는다.

실제 입력값을 3개 색상과 위아래로 나뉜 3개 구간에 표시한다. 세 채널의 공통 최대 절댓값은 시각화 스케일에만 사용한다. 모든 값이 0인 경우도 처리한다. SVG 좌표는 정수로 변환하며 시간·난수·삼각함수를 사용하지 않는다. 모델로 전달할 원본 데이터는 정규화·채널 복제·제로 패딩하지 않는다. 채널 번호는 입력 배열의 순서이며 임의의 지진계 방향을 가정하지 않는다. 시간 단위 대신 샘플 인덱스를 표시한다.

## API와 기존 기능 유지

- STEAD: 기존 `{sample_id}` 요청을 그대로 지원하며 서버 보관 파형을 전달한다. 클라이언트가 첨부한 파형은 이 경로에서 무시한다.
- 사용자 JSON: 브라우저가 Next.js `/api/predict`에 `{source:"json", sample_id, waveform}`을 전송한다. Next.js는 재검증 후 기존 FastAPI `/predict`에 `{sample_id, waveform}`을 전달한다.
- Next.js는 요청 스트림을 1 MiB까지 읽으며 Content-Length를 신뢰해 검사를 생략하지 않는다.
- 응답 샘플 ID가 요청 ID와 일치해야 한다. ID·클래스·신뢰도 범위 검사를 유지한다.
- 클래스 매핑은 기존 학습 코드 근거를 유지한다: **0=Micro Earthquake(미소지진), 1=Macro Earthquake(강진), 2=Noise(노이즈)**.
- `/health`, FastAPI `/predict`, PostgreSQL 저장 코드는 변경하지 않는다. 동일 출처 Next.js 중계 구조를 유지한다.
- 화면 이력은 이번 세션에서 성공한 실제 응답 목록이다. 전체 DB 이력 조회는 추가하지 않는다.
- 마이크·1채널 변환·라이브러리 추가는 없다. 백엔드·Docker·DB 스키마·모델·원본 HDF5를 변경하지 않는다.

원본 자동 생성 파일을 변경하지 않기 위해 임시 복사본을 Node.js 24.21.0 및 Next.js 16.4.0 webpack 개발 서버로 실행했다.

## 메뉴가 보이지 않는 문제의 후속 검증

2026-10-09 확인 당시 `app/page.tsx`에는 세 메뉴가 있었지만, 실제 `localhost:3000` HTML은 DAY 16 화면과 JSON 미지원 문구를 반환했다. 개발 서버의 작업 디렉터리가 현재 프로젝트임을 확인하고 해당 3000 포트 서버만 재시작했다. 재시작 후 DAY 17 HTML과 세 버튼이 실제 응답에 포함됐다. UI와 API 코드를 다시 구현할 필요는 없었다.

설치된 Windows Chrome을 별도 임시 프로필의 헤드리스 브라우저로 실행해 실제 `http://localhost:3000`에 접속했다. 다음 5개 확인이 통과했다.

1. DAY 17 및 `STEAD 샘플 / JSON 붙여넣기 / JSON 파일` 버튼이 모두 표시된다.
2. JSON 붙여넣기를 실제 클릭하면 텍스트 입력창과 `JSON 검증 및 파형 표시` 버튼이 나타난다.
3. JSON 파일을 실제 클릭하면 파일 선택 영역이 나타난다.
4. STEAD 샘플로 돌아오면 기존 샘플 선택 영역이 나타난다.
5. 390px 모바일 뷰포트에서도 세 메뉴가 모두 표시된다.

재현 명령(프로젝트 루트에서, 기존 Windows 가상환경 및 Chrome 사용):

```bash
.venv/Scripts/python.exe seismic-ai-dashboard/scripts/verify-input-menus.py
```

새 라이브러리는 설치하지 않는다. 검증은 추론 요청을 보내지 않으며 DB 기록을 추가하지 않는다. 테스트 Chrome 프로세스와 임시 프로필만 정리한다. 기존 자동 테스트 57건도 다시 통과했다.
