## DAY 15 현재 범위

- 기존 디자인을 유지하고 FastAPI `GET http://localhost:8000/health` 연결만 검증한다.
- 브라우저는 같은 출처의 Next.js `/api/health`를 호출한다. Next.js 서버가 FastAPI에 요청하므로 브라우저 CORS 설정을 위해 백엔드를 변경할 필요가 없다.
- 정상 HTTP 응답이며 JSON의 `status`가 `ok`이면 `연결됨`, 오류·비정상 응답·시간 초과이면 `연결 안 됨`을 표시한다. 최초 요청 전에는 `확인 중`을 표시한다.
- 페이지 진입 시 확인하고, 이전 확인 완료 후 15초 뒤 다시 확인한다. 서버 측 요청 제한 시간은 5초, 브라우저 측은 7초다.
- `/predict`, `/predictions`, Docker, PostgreSQL, AI 모델 코드는 이번 단계에서 변경하지 않는다.

### 실제 실행 검증 절차

1. `seismic-ai-dashboard`에서 `npm run dev`로 Next.js를 실행한다. 터미널에 표시된 포트를 사용한다.
2. FastAPI 실행 상태에서 `/api/health`가 HTTP 200 및 `{"status":"ok"}`를 반환하고, 대시보드가 `연결됨`을 표시하는지 확인한다.
3. FastAPI를 중지하면 다음 확인에서 `/api/health`가 HTTP 503을 반환하고 `연결 안 됨`이 표시되는지 확인한다.
4. FastAPI를 재시작하면 다음 확인에서 `연결됨`으로 복구되는지 확인한다.
5. 브라우저 네트워크 탭에서 `/api/health`만 호출하며 `/predict`, `/predictions` 요청이 없는지 확인한다.

`/api/health`의 404는 Next.js 경로를 찾지 못했다는 뜻이며 FastAPI CORS 오류가 아니다. 프로젝트 실행 경로와 포트를 확인하고 Next.js 개발 서버를 재시작해 새 Route Handler가 인식되는지 확인한다.

`localhost:8000`은 Next.js 서버가 실행되는 환경을 기준으로 한다. 이후 컨테이너나 원격 배포 환경에서는 서버 간 주소를 별도로 검토한다.

## 후속 기능의 필수 요구사항

### 클래스와 매핑

- 최종 결과 클래스는 강진(Macro Earthquake), 미소지진(Micro Earthquake), 노이즈(Noise) 세 가지다.
- 최종 결과 화면에서 단순 `Earthquake` 분류를 사용하지 않는다.
- 클래스 매핑은 DAY 16에 확인했다: 0=미소지진, 1=강진, 2=노이즈. 구현 전에 학습 코드의 라벨 생성 및 인코딩, 모델 출력 순서를 확인하고 파일 경로와 근거를 기록한다. 이름의 나열 순서로 매핑을 추측하지 않는다.
- DAY 14의 `Earthquake` 및 고정 수치는 DAY 16 UI에서 제거했다. 실제 API 응답만 세 클래스 기준으로 표시한다.

### 입력

- 목표 입력 방식: STEAD 샘플 선택, JSON 또는 파일 입력, 마이크 녹음.
- 모델 입력 규격: `(1000, 3)`. 1000개 시간 샘플, 각 샘플당 정확히 3채널을 검증한다.
- 숫자 타입, 유한성, 누락값, 배열 구조 및 길이를 검증한다. 형식이 맞지 않는 데이터를 추론에 전달하지 않는다.
- DAY 16에서 짧은 1차원 예시를 제거하고, 지정 STEAD 샘플의 (1000, 3) 규격과 유효성을 검증한다.
- 향후 1채널 → 3채널 변환을 추가할 수 있지만, 채널 복제 또는 0 채우기는 실제 3축 측정값 복원이 아니다. 연구용 변환으로 표시하고 적용한 방식을 기록한다.
- 마이크는 실제 지진계와 특성이 다르므로 모델 성능 검증 전까지 실험용 기능으로 구분한다.

### 결과와 이력

- 클래스 이름, 신뢰도, 실제 입력 파형, 샘플 ID를 표시한다.
- 추후 PostgreSQL의 저장 이력과 연결한다.
- 합성 파형·예시 결과와 실제 입력·모델 출력·저장 이력을 명확하게 구분한다.
- 실제 연결된 기능만 사용 가능한 동작으로 제공한다.
